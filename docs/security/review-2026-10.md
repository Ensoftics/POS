# Security review — October 2026 (Slice 14a)

An internal code and configuration review of the API, web app, Android app and database
before the pilot. It is **not** a substitute for an independent penetration test, which should
happen before general availability (see "Still to do").

## Scope and method

- **Code read across every layer:** authentication and sessions; authorisation; tenant
  isolation; input handling; file uploads; outbound integrations (PayHere, Notify.lk,
  S3, SMTP); logging; configuration; and Android storage and transport.
- **Automated checks added**, which now run in CI so these properties cannot quietly regress:
  - `apps/api/src/security/route-protection.spec.ts`:
    - every API route must declare `@RequirePermissions`, `@SelfService` (the caller's own
      data) or `@Public`;
    - public routes must appear in a reviewed list with the reason they are public;
    - platform routes need the platform guard.
  - `apps/api/test/security.int-spec.ts`, against the live schema:
    - every table that names a business has row-level security forced with a policy;
    - the application role is not a superuser, does not bypass RLS and owns no tables;
    - it cannot truncate anything or touch the migrations table;
    - evidence tables (sales, returns, ledgers, stock movements, audit and consent
      history, payment events) are append-only for it.
- **Dependency audit:** `pnpm audit --prod`.

## Confirmed in place (no change needed)

- **Sessions:**
  - JWTs pinned to HS256 with issuer and audience checks; each request re-checks the
    session and the live membership.
  - Refresh tokens rotate, and reuse is detected per token family.
  - Refresh, reset, verification and invitation tokens are stored only as SHA-256 hashes.
  - The web refresh cookie is `HttpOnly`, `SameSite=Strict`, `Secure` in production and
    scoped to `/api/v1/auth`; the refresh call also needs the client header (CSRF).
- **Passwords:**
  - scrypt with N = 2^16;
  - account lockout after repeated failures; unknown e-mails get a constant-time dummy
    hash;
  - a stricter rate limit on authentication routes.
- **Tenant isolation:**
  - the tenant comes from the verified token, never from the request;
  - every tenant query runs inside `withTenant`, which RLS enforces;
  - cross-tenant tests exist for each module.
- **Platform console:** separate token audience, mandatory TOTP with replay protection,
  append-only audit, and no access to trading data.
- **Inputs:**
  - every body and query is parsed by Zod schemas, which drop unknown keys;
  - raw SQL uses parameters only (`Prisma.raw` appears only with fixed table aliases);
  - framework error messages are replaced with fixed text.
- **Uploads:**
  - in memory with a size cap;
  - type checked by file signature, then re-encoded (no SVG; EXIF/GPS removed);
  - stored in a private bucket behind HMAC-signed links.
- **Integrations:**
  - PayHere notifications are verified (signature, amount, idempotency);
  - Notify.lk and S3 credentials go only in request bodies or headers, never in URLs or
    logs.
- **Web:**
  - no raw HTML injection;
  - access tokens are kept in memory only;
  - the only post-login redirect is limited to `/platform` paths.
- **Logs:** no request bodies, query strings, tokens or message contents; e-mail failures
  log only IDs.

## Still to do (outside this code review)

- **Independent penetration test** of the deployed pilot environment.
- **Web hosting headers:** a Content-Security-Policy, HSTS, `frame-ancestors 'none'` and
  related headers on the web app's host. They belong to the hosting configuration and are
  delivered with the deployment files (Slice 14c).
- **Shared rate limiting:** rate-limit counters are kept in memory per API instance.
  Running more than one instance needs the Redis-backed store, or a limit at the load
  balancer.
- **Secrets:**
  - keep secrets in the host's secret manager, not in `.env` files on servers;
  - rotating `JWT_ACCESS_SECRET` signs everyone out, re-keys image links, and makes stored
    platform TOTP secrets unreadable (operators re-enrol with `platform:admin reset-totp`).
- **Dependency watch:** run `pnpm audit --prod` in CI on a schedule, and re-check the
  accepted Expo tooling advisories (S-10) on upgrades.
